REPROVADO. Com dois usuários distintos logados simultaneamente (FRED e QA), o usuário ocioso (com a tela "Processar Declarações" aberta e vazia) passou a exibir ao vivo os contadores e a barra de progresso do processamento do OUTRO usuário — exatamente o comportamento que o PBI-7582 deveria eliminar. Por que ainda vaza — o fix não está no build de HML AXA

O código da correção existe na branch feat/7582-new-di-duimp-contadores (hub isola por grupo do usuário via Clients.Group(userId) e a view chama joinGroup(userIdHub)). Porém, inspecionando o JavaScript servido em produção-HML AXA (inline da página + DIProcessamento.js), a chamada joinGroup não existe (0 ocorrências), assim como userIdHub / nomeUsuario. O cliente conecta ao hub e registra os handlers ContadoresDI/AddProgress, mas nunca entra no grupo do usuário — e ambos os usuários recebem as atualizações (comportamento de Clients.All / broadcast global, o bug original).

Descrição e Critérios de Aceite

Ao final do processamento de Declarações/Adições (DI/DUIMP) são exibidos quatro contadores — Lidas, Desprezadas, Inconsistentes e Incluídas — atualizados em tempo real via SignalR (hub DIProcessamentoHub). O PBI corrige o problema de os valores se misturarem/"piscarem" entre sessões quando dois usuários processam concorrentemente.

  • CA01 — Isolamento por sessão: cada usuário vê apenas os contadores da própria execução. Não atendido
  • CA02 — Estabilidade: os valores exibidos não se alteram por execução de outro usuário. Não atendido
  • CA03 — Consistência durante o processamento: incrementos refletem só a própria sessão. Não atendido
  • CA04 — Independente do tipo de declaração (DI's / DUIMP's / ambos). Não atendido
Casos de Teste — Reteste de Isolamento
Método: observador ocioso + concorrência real (2 usuários)
O detector mais direto do bug: o usuário B fica OCIOSO na tela de Processamento (contadores vazios) enquanto o usuário A processa. Com o fix funcionando, a tela de B permanece vazia. Sem o fix (broadcast global), a tela de B passa a exibir os contadores e o progresso de A.
CT-WIS-001P1 Isolamento por sessão — B ocioso NÃO deve ver os contadores/progresso de A (DI's)
REPROVADO

CA01 (isolamento) + CA02 (estabilidade)

A = FRED (processa) · B = QA (ocioso, observando)

  1. Logar FRED (sessão A) e QA (sessão B) em navegadores/contextos distintos; ambos abrir WI/Siscomex → Declarações Adições → Processamento.
  2. [B] Deixar a tela de Processamento aberta e vazia (contadores em branco), sem interagir.
  3. [A] Filial 0001, Apólice 2501062203607, Critério Desembaraço (Jan/2026), Mês/Ano 07/2026, marcar Processar DI's, clicar Processar → Sim.
  4. Enquanto A processa, observar continuamente a tela de B (texto dos contadores e barra de progresso).

A exibe Lidas:3 / Desprezadas:2 / Inconsistentes:1 / Incluídas:0. A tela de B permanece vazia durante todo o processamento de A.

✗ Obtido: a tela do usuário B (QA), com o formulário vazio, passou a exibir "Lidas: 3 · Desprezadas: 2" e a barra "Processando Adição nº 2601817193/001 — 75%" — espelhando o processamento de A em tempo real. Sequência capturada em B: t+1,8s → "Lidas:0…" + 25%; t+1,9s → "Lidas:3 Desprezadas:2…" + 75%. Reproduzido 2×. CA01 e CA02 não atendidos.
