Grupo 3 — Reprodução da condição exata do bug (prova do fix)

PROVA▼
REPRO-7751POST /Gravar com c_gar_cit_str="M;" (payload que estourava) → tratado graciosamenteFIX CONFIRMADO

Contexto

O bug ocorria quando o campo composto c_gar_cit_str chegava como "M;" (código de garantia vazio após o ;): o código antigo fazia int.Parse(c_gar_cit_str.Substring(2)) = int.Parse("") → FormatException → HTTP 500 → modal genérico "ATENÇÃO! Erro ao tentar enviar os dados." O fix (PR #1808) troca por Split(';') + int.TryParse.

Observação: a condição c_gar_cit vazio não existe naturalmente em HML (0 registros NULL confirmado via SQL) e a UI recupera garantia NULL para um valor válido — por isso o payload exato foi disparado diretamente no endpoint /AverbacaoInternacional/Gravar (mesma sessão/tokens), exercitando o código server-side corrigido.

Resultado

✓ HTTP 200 com resposta de negócio limpa: {"codigo":0,"lista":"Erro|Informar a Garantia;\r\nInformar o Navio;"}
✓ NÃO ocorreu HTTP 500 nem o modal "Erro ao tentar enviar os dados" (comportamento do bug original)
✓ O "M;" foi tratado graciosamente (Split+TryParse → c_gar_cit=0 → validação normal) → fix deployado e efetivo na build alfa AXA
EV — payload c_gar_cit_str="M;" retornando HTTP 200 gracioso (sem crash)
