2. Descrição

DUIMPs marcadas para reprocessamento (sts_prc='R', correção de Data de Saída via tela “DUIMP sem Data de Saída”) nunca concluem o reprocessamento, mesmo depois do fix do #8759. O WorkerDUIMP pega a DUIMP em todo ciclo, tenta processar, mas o registro nunca sai de R — loop infinito silencioso, sem nenhum erro no log.

Causa raiz (confirmada no código): AtualizaStatusAsync (~linha 480) tem a cláusula WHERE … AND (sts_prc = 'P' OR sts_prc = 'E') — escrita quando o modelo só tinha P/E. O merge ADO-8255/8258 introduziu os estados I (Inconsistente) e R (Aguardando reprocessamento) sem revisar esse código; com a DUIMP em R, o UPDATE não casa nenhuma linha, ExecuteNonQueryAsync() retorna 0, e o método devolve (false, "Nenhuma DUIMP encontrada…") sem lançar exceção. O chamador (DuimpProcessamentoService.cs:248) não verifica esse retorno → descartado silenciosamente. Fix (DoD): WHERE aceitar R (avaliar também I) + o chamador verificar o booleano e logar/alertar quando 0 linhas.
Nota de fase: card em desenvolvimento/homologação; validação in loco na execução (pós-deploy). Sem PII: os números de DUIMP e dados de reprodução ficam apenas no card AzDO (privado), não neste plano público.

3. Escopo

In scope

  • DUIMP em sts_prc='R' sair de R (concluir) após o fix — o UPDATE de status passa a casar a linha.
  • Regressão dos estados antigos P e E; observabilidade do chamador (log/alerta quando 0 linhas).
  • Avaliação do estado I (se algum fluxo atualiza status a partir dele).

Out of scope

  • A exceção de Embalagem/Adicao null — é o #8759 (pré-requisito para o reprocesso chegar até aqui).
  • Produção — QA não testa em PROD (N/A).

4. Pré-requisitos

Gates de execução (externos — não dependem do QA):
  1. Fix do #8779 deployado (WHERE aceitar R + chamador verificar retorno).
  2. #8759 também aplicado (senão o reprocesso nem chega a atualizar o status — exceção antes).
  3. Massa: as DUIMPs de reprodução em sts_prc='R' (identificadas no card) disponíveis; acesso ao banco (status/averbação) e ao log do Worker.
