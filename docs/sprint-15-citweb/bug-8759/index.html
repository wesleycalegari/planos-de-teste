2. Descrição

Ao reprocessar uma DUIMP corrigida pela tela “DUIMP sem Data de Saída” (sts_prc='R'), o WorkerDUIMP lançava ArgumentNullException ao processar o campo CD_TIPO_EMBALAGEM quando a coleção Embalagem vinha null (não vazia) no JSON salvo — a DUIMP nunca avançava e o erro se repetia a cada ciclo (~37s).

Causa raiz / fix (confirmado no código): Embalagem.FirstOrDefault() lançava porque o ?. protegia só o item retornado, não a coleção Embalagem nula. Fix: dadosDeclaracaoResponse.Embalagem?.FirstOrDefault()?.CD_TIPO_EMBALAGEM…, aplicado nos dois métodos (ProcessaDUIMP síncrono e ProcessaDUIMPAsync). DoD também pede avaliar o mesmo padrão em outros campos (ex.: Adicao.FirstOrDefault()).
⚠️ Interdependência com o #8779: corrigir esta exceção faz o Worker não quebrar, mas o reprocesso só conclui de ponta a ponta (status R → concluído + averbação) quando o #8779 também estiver corrigido (a cláusula WHERE de AtualizaStatusAsync não aceita sts_prc='R', deixando a DUIMP em loop silencioso). Por isso o CT de conclusão ponta a ponta (CT-WEM-002) fica gated pelo #8779. Sem PII neste plano público (DUIMP/CNPJ reais só no card).

3. Escopo
