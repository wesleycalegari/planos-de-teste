Três flags de envio de prévia — cada uma tem comportamento distinto na coluna U:
  • Flag 1 — Envio automático: seguradora configura uma data fixa mensal; ao alterar o status automaticamente para PRÉVIA LIBERADA PARA O CORRETOR, o sistema grava data/hora na coluna U.
  • Flag 2 — Envio manual: seguradora gera prévia no CITWEB (Fechamento Mensal → Prévia), depois libera para o corretor. Coluna U registrada na geração (EM PRÉVIA) e substituída na liberação (PRÉVIA LIBERADA PARA O CORRETOR).
  • Flag 3 — Gerado pelo corretor via CITNET: movimento disponível sem ação da seguradora. Coluna U permanece em branco. Se a seguradora gerar prévia manual mesmo assim, registra a data sem alterar o status para EM PRÉVIA.
⚠️ Validação em staging concluída em 11/05/2026 (Fabíola Costa): Flag 2 (geração + liberação) — OK · Flag 2 (liberação sem geração) — OK · Flag 3 — OK · EM EMISSÃO INTERFACE — OK · FATURA EMITIDA — OK. Apólices usadas em staging: 101054 (sub 001/002), 110159 (sub 001/002), 590359 (sub 001) para Flag 2; 121254 (sub 001/002), 050659 (sub 001/002) para liberação direta; Flag 3 validada mas número não registrado. Confirmar apólices equivalentes no HML KOVR antes de executar.
Critérios de aceite (síntese)
  • CA-1: Status EM PRÉVIA → data/hora da geração gravada na coluna U (comportamento existente, deve ser mantido).
  • CA-2: Status PRÉVIA LIBERADA PARA O CORRETOR → data/hora da liberação gravada na coluna U.
  • CA-3: Se houver geração antes da liberação → data da geração substituída pela data da liberação.
  • CA-4: Se não houve geração prévia → coluna U preenchida diretamente com data/hora de liberação.
  • CA-5: Sem cenários onde coluna U permaneça em branco após liberação (exceto Flag 3).
  • CA-6: Sobrescrita obrigatória quando houver liberação após geração.
  • CA-7: Formato DD/MM/AAAA HH:MM:SS.
  • CA-8: Flag 3 → coluna U em branco (ausência é o comportamento esperado).
Pré-requisitos e massa de dados
  • Ambiente HML KOVR acessível: https://kovr-hml-faturamento.nsseg.com.br/login/
  • Credenciais operador: FRED / DERF · gestor: ADMCIT / MSTCIT
  • Apólice(s) Flag 2 com averbações no período corrente e subgrupo acessível — confirmar no banco HML KOVR (sugestão: apólices 101054 / 110159 se existirem em HML).
  • Apólice(s) Flag 2 com status MOVTO RECEBIDO PELO CITNET e coluna U em branco — para CT-PRV-003.
  • Apólice(s) Flag 3 com averbações via CITNET — localizar via banco HML KOVR antes de executar.
  • Nenhuma prévia gerada no período corrente para as apólices de teste (estado inicial limpo). Se necessário, usar período anterior inativo.
  • Navegação sempre por clique a partir do login — nunca colar URL interna na barra do navegador.
