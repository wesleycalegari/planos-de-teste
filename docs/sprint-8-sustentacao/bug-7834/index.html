1. Descrição
Bug reportado: No Conversor de Exportação do CITNET CHUBB, a conversão estourava ConversorController.Converter — Index was outside the bounds of the array. Documento vazia, preencha os dados corretamente e tente novamente! (versão 1.00.13, 17/07/2026). A funcionalidade de Exportação ficava indisponível / não gerava os arquivos.
Root cause (dev — Ivan): em CitNetService/ConversorService.cs → ConverterLinha, o acesso a colunasPlanilha[indice] (layout mapeado por coluna de planilha) estourava IndexOutOfRange quando o índice da coluna mapeada ultrapassava o número de colunas da linha (ou documento vazio). A exceção era capturada e reembrulhada na mensagem genérica "... vazia, preencha os dados corretamente...". Fix: commit 22225c0b / PR #1859 — adiciona bounds check em colunasPlanilha[indice]: campo tratado como vazio → linha rejeitada com mensagem clara quando obrigatório, ou aceita quando não obrigatório.
Validação do dev: RED→GREEN via harness de console contra o CitNetService.dll (config CHUBB, binário real) — sem o fix reproduz a exceção idêntica ao card; com o fix trata o campo vazio. + fluxo geral de upload validado em 2 ambientes reais (IIS local e HML chubb-hml-faturamento.nsseg.com.br/citnet, Filial 100 / Ramo 21 / upload .xlsx → grid populado, zero erros).
2. Critérios de Aceite
  • CA1 — Converter uma planilha de Exportação cujo layout mapeia uma coluna de Documento além dos limites da linha (ou com o documento vazio) não deve mais estourar Index was outside the bounds of the array. A linha deve ser rejeitada com mensagem de negócio clara (ex.: "CONTEÚDO NÃO ESTÁ PREENCHIDO") quando o campo é obrigatório, ou aceita quando não é.
  • CA2 — O fluxo geral do Conversor CHUBB (upload de planilha, importação) continua funcionando após o fix (sem regressão).
  • CA3 — (Desejável) Uma planilha de Exportação válida (documento preenchido) converte/processa com sucesso, gerando averbação.
3. Pré-requisitos e Riscos de Execução
⚠️ BLOQUEIOS A RESOLVER ANTES DA EXECUÇÃO (destacados para o Wesley):
  • Acesso CHUBB: não há credenciais CHUBB no .env. O dev acessou via "bypass de teste NSTECH". Ambiente: chubb-hml-faturamento.nsseg.com.br/citnet (não /alfa/). Preciso do usuário/senha CITNET CHUBB HML.
  • Layout de Exportação (o trecho corrigido): a ressalva do dev diz que o único layout disponível no ambiente de teste (NSTECH) é de largura fixa — não mapeado por coluna de planilha, que é exatamente a linha corrigida. Sem um layout de Exportação mapeado por planilha, o CA1 não é exercitável pela UI (o dev avaliou criar um de ~38 campos e descartou). Preciso do layout real de Exportação CHUBB (ou autorização para criá-lo).
Enquanto os dois itens não forem resolvidos, o CA1 (linha exata do fix) fica BLOQUEADO por acesso/massa externa; a evidência primária permanece o RED→GREEN de console do dev. O CA2 (regressão do fluxo geral) é executável assim que houver acesso CHUBB.
