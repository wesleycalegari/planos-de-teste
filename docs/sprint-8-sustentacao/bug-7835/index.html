1. Descrição
Bug reportado: os arquivos de log do CITNET (CHUBB) registravam todos os comandos SQL executados, inflando os arquivos (centenas de MB), misturando ruído com os erros reais e criando risco de performance/disco. Adicionalmente, o log gravava a connection string completa (senha em texto puro).
Root cause (confirmado em código): CitNetUtility/DbUtility.cs → Consultar() (compartilhado por TODAS as 24 CIAs) gravava incondicionalmente, a cada chamada: GravarLogErro("Valor da sConexao: " + sConexao) (linha 157 — vazamento de senha), "Iniciando consulta: " + strSql (224) e "Executando comando SQL: " + commandText (279). Fix: PR #1860 — log de SQL vira opt-in via flag habilitaLogSql (default desligado), remove o log da connection string/senha e mantém os logs de erro reais.
Validação do dev (medição real): comparação antes/depois no LogErro*.txt do servidor CHUBB, mesma máquina/dia — blocos de log 208 → 29, ocorrências do padrão de ruído SQL 132 (63%) → 0, e (local) linhas -92% / tamanho -94%. Com habilitaLogSql=S o detalhado volta (opt-in). Senha "Valor da sConexao" não aparece em nenhum modo. Log de erro real intacto.
2. Critérios de Aceite
  • CA1 — Por padrão (sem habilitaLogSql=S), o log do CITNET NÃO registra os comandos SQL completos ("Executando comando SQL:" / "Iniciando consulta:").
  • CA2 — O log NÃO registra a connection string / senha ("Valor da sConexao:") em nenhum modo.
  • CA3 — Os logs de erro reais continuam sendo registrados de forma clara (rastreabilidade preservada).
  • CA4 — Com habilitaLogSql=S (opt-in), o log detalhado de SQL volta a aparecer (parametrização funciona).
