Contexto do Bug

Descrição original: No Conversor RCTR-C, quando o arquivo de entrada continha CNPJ Embarcador alfanumérico (ex.: 1A2B3C4D5E6F35), o campo Percurso era montado como UNDEFINED/UNDEFINED em vez de usar os valores de Estado Origem e Estado Destino (ex.: SP/SP). Isso causava a rejeição de todos os registros válidos.

Comportamento esperado: O sistema deve aceitar CNPJ alfanumérico e resolver o Percurso corretamente a partir dos campos EST_ORIG e EST_DEST do arquivo.

Ambiente afetado: CITNET STARR ALFA HML — mesmo ConversorController do BUG-7541 (EZZE).

Fix: Mesmo PR que corrigiu o BUG-7541 (EZZE) — ConversorController compartilhado entre seguradoras. Após o fix, o Percurso é lido corretamente dos campos de Estado.

✔ FIX CONFIRMADO — CNPJ alfanumérico aceito, Percurso resolvido como SP/UB (não UNDEFINED/UNDEFINED)
