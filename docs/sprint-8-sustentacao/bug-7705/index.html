Descrição do Bug e Correção

Cenário Original (com bug)

Ao acessar Conversor de Arquivos no CITNET KOVR HML ALFA e selecionar um ramo (RCV/59 ou RCTR-C/54), o sistema não carregava o layout de conversão. O combo de Layout permanecia vazio, impedindo importar/converter arquivos — o módulo ficava inoperante para o usuário SEGURADO.

Causa Raiz (documentada pelo dev)

No épico CNPJ alfanumérico, hdIdUsuario / Session[idUsuario] passou a ser o documento (u_cpf_cgc paddado, ex.: 00000776000116), que não casa com o value da option do combo Segurado (c_idt_pes / código 776000116). Em CarregaSegurado (conversor.js), o perfil SEGURADO não auto-selecionava o segurado → combo de Layout ficava vazio.
O erro HTTP 500 "Erro Consulta Arquivo de Layout" relatado era um deploy-gap do card original #7616, já resolvido no build anterior.

Fix Aplicado (PR #1822)

Para o perfil SEGURADO não-AXA: se val(idUsuario) não casar com nenhuma option, seleciona por clientes[0].c_idt_pes (o código, que casa com a option) — restaurando a auto-seleção do segurado e o carregamento do combo de Layout.

Critérios de Aceite

  1. Ao selecionar o ramo no Conversor, o segurado é auto-selecionado (perfil SEGURADO)
  2. O combo de Layout é populado, permitindo escolher/criar layout de conversão
  3. Não é exibida a mensagem "Erro Consulta Arquivo de Layout" (nem outro erro)
  4. Comportamento consistente em múltiplos ramos (RCV/59 e RCTR-C/54)
