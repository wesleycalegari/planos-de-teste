Descrição do Bug
Problema original: Ao selecionar uma data sem câmbio disponível (além da janela de câmbio registrado), o sistema deveria bloquear/alertar o usuário e zerar o campo câmbio. Em vez disso, mantinha o valor previamente carregado sem qualquer aviso — permitindo gravar a averbação com câmbio incorreto.

Módulos afetados: Importação Definitiva, Exportação e RCT-VI (todos na aba Internacional do CITNET).

Cenário de reprodução: Apólice com moeda 220 (USD) → Data com câmbio válido (08/06/2026 = 5,16950) → Alterar para data sem câmbio (01/08/2026) → campo não era zerado e nenhum alerta era exibido.
Critérios de Aceite
1. Importação Definitiva: Ao selecionar Data de Saída com câmbio disponível (08/06/2026), campo Câmbio deve exibir 5,16950.
2. Importação Definitiva: Ao alterar para data SEM câmbio (01/08/2026), sistema deve exibir alerta “Não foi possível obter o câmbio da Apólice e da Moeda Provisória. Favor contatar a Seguradora!” e zerar o campo câmbio.
3. Exportação: Data 08/06/2026 → câmbio 5.1695 carregado no campo oculto. Data 01/08/2026 → alerta “Não foi possível obter o câmbio do DÓLAR NORTE-AMERICANO para a data de saída informada!”.
4. RCT-VI: Data 08/06/2026 → sem alerta (câmbio OK). Data 01/08/2026 → alerta “Não foi possível obter o câmbio da Apólice. Favor contatar a Seguradora!”.
✔ Status do reteste: Todos os 3 casos de teste APROVADOS no ALFA. Fix confirmado nos 3 módulos afetados.
Massa usada: Importação: Apólice 7 / Subgrupo 1 / Filial 1. Exportação: Apólice 3 / Subgrupo 1 / Filial 1. RCT-VI: Filial 1 (sem apólice selecionada — handler independente).
Último câmbio disponível (moeda 220 em ALFA): 01/07/2026 = 5,0000 · 01/08/2026 = 0 (sem registro).

Observações Técnicas
Câmbio moeda 220 no ALFA: 08/06/2026 = 5,16950 · 01/07/2026 = 5,0000 · 01/08/2026 = 0 (sem registro). Datas a partir de agosto/2026 não possuem câmbio no ALFA HML.

Diferença de handler por módulo no ALFA:
• Importação Definitiva: evento change (datepicker) — verifica câmbio apólice (moeda 220) E câmbio moeda provisória (#c_moe_tmp) separadamente.
• Exportação: evento change (datepicker) — verifica apenas câmbio moeda 220; alerta vem da função ObterCambio.
• RCT-VI: evento focusout — verifica câmbio moeda 220 com alerta explícito no handler.

Campo câmbio por módulo: Importação usa v_cbi_moe_uss (hidden) e v_cbi_moe_tmp (visível) · Exportação usa v_cbi_moe_uss (hidden) · RCT-VI não exibe campo câmbio no form—alerta é o mecanismo de bloqueio.
