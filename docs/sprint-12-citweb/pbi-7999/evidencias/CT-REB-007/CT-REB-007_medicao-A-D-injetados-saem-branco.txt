CT-REB-007 — MEDIÇÃO in loco de A (AWB) e D (Outro documento) na Relação de Embarques

MÉTODO (autorizado): como o produto NÃO oferece A/D pela tela (combo só C/N/M/O),
os códigos foram INJETADOS via SQL em 2 linhas do fechamento (como se injeta 'X' fora
do domínio), o relatório foi REGERADO pelo fluxo real e a célula Tipo de Documento lida.
Reversível — as 2 linhas foram restauradas para 'O' ao fim.

  u_avb 2026004113 · e_doc_ebq='A' (injetado) · célula Tipo de Documento = '' (VAZIA)
  u_avb 2026004115 · e_doc_ebq='D' (injetado) · célula Tipo de Documento = '' (VAZIA)

  mapa observado no mesmo arquivo:
    C -> CTE      N -> NF Eletrônica     M -> MDF-e     O -> Outros
    A -> ''(vazio)   D -> ''(vazio)   <- caem no default->"" do helper

VEREDITO: N/A por decisão de produto (MEDIDO).
  O domínio de Tipo Documento do RCV é {C,N,M,O} (combo da tela + inventário das 4 bases,
  medido 14/08). A e D estão FORA do domínio. Quando forçados via SQL, o relatório os
  deixa em BRANCO (default->"") — não inventa rótulo, não vira MDF-e, não mostra código
  cru. É o mesmo tratamento correto do código vazio (CT-REB-006, APROVADO). Portanto
  A/D não exigem tradução: não há defeito. Se Produtos decidir incluir A/D no domínio,
  é card próprio (cadastro + relatório), não regressão deste PBI.
