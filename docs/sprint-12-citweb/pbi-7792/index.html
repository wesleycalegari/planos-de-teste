Por que este plano é consolidado

O PBI #7792 não é uma correção pontual: é a substituição do CITNET por uma reescrita completa (front React + API própria /api/…, multi-tenant com 17 ambientes no combo de login), que precisa ser provada idêntica ao sistema atual antes de assumir o lugar dele. Cada task filha é uma tela em paridade, não um bug isolado — por isso um plano só, com um grupo de CTs por tela e um placar único no card pai.

Fato que sustenta o método: os dois sistemas apontam para a mesma base do tenant em execução — hoje smt-hom-citweb-tokio (era smt-hom-citweb-axa-alfa até a reancoragem de 06/08) — e os protocolos saem sequenciais entre eles, fato reconfirmado na bateria da Tokio em 06–07/08. Então dá para gravar em um e conferir no outro, e o diff definitivo é coluna a coluna no banco, não impressão de tela. O oráculo de valor nunca é o comportamento de um dos sistemas: é o cadastro da condição comercial.

Este plano não começa do zero. Três rodadas de QA já mapearam os apontamentos nominais (D1–D8, P1, A1, R1, R2, C1–C3) e o dev declarou correção para a maior parte deles. Cada CT aqui é o reteste de um apontamento nomeado ou a cobertura de uma área ainda não varrida — o veredito do CT é o veredito do apontamento.
