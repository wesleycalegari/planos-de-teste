Objetivo. Automatizar de ponta a ponta os fluxos do CITWEB Allianz. O adicional único da Allianz é a integração das Caixas Postais com a plataforma AT&M / NSOne (Averba). Regra-chave confirmada no código e em tela: o vínculo depende do SEGURADO da apólice ter terminal cadastrado no Averba (a tela Cadastro Instalação ATM consulta o Averba pelo CNPJ do segurado — CadastroInstalacaoAtmController.cs:371).
Escopo (revisto 28/08/2026). A automação da Allianz cobre apenas: (1) Cadastros — Segurado, Corretor, Apólice (incl. a apólice de origem AT&M que habilita o botão de vínculo), Subgrupo e Filial; (2) Caixas Postais — vínculo manual (CITWEB) e automático (botão Cadastro Instalação ATM → Averba/NSOne), mais o Gerenciamento de Caixas ATM. Os demais módulos do launcher (Internacional, Conversor, Importar/Exportar, Interface WI/Siscomex, Liberação de Cobertura, Gestão, Tabelas) e o restante do Nacional (Averbação/Fechamento/Relatórios) ficam fora de escopo — ver a seção «Fora de escopo». Sem CNPJ/nome de cliente/credencial (regra 11); massa sempre descoberta em runtime.

CT-ATM-007-LIVEP1PositivoEnviar "A" ao vivo → grava vínculo automático (mutação AT&M)
Bloqueado

O Enviar só roteia para "A" (que grava o vínculo) em terminais rotulados (PARCEIRO) (controller l.415); terminal não-parceiro cai em "M" (Migração) e NÃO grava vínculo. Na massa HML Allianz não há terminal PARCEIRO pristino/não-compartilhado para um "A" novo e reversível (todos em M/E, A/P ou compartilhados entre apólices). Disparar "A" sobre eles seria um POST irreversível ao Averba sobre caixa em estado inconsistente — por isso NÃO foi disparado. Teste guardado (test_ct_atm_007_vinculo_automatico.py, test B): quando existir massa PARCEIRO segura, descobre dinamicamente, executa o Enviar "A", valida sucesso+protocolo+tb_cad_cx_atm(A)+tb_sgp_col_cit e faz teardown. ⛔ Nunca "C" (criar terminal é irreversível).

Evidências
Bloqueado — Enviar não disparado (ver o bloqueio no CT); banco intacto.

A automação da Allianz limita-se a Cadastros (Segurado, Corretor, Apólice origem-AT&M, Subgrupo, Filial) e Caixas Postais (vínculo manual + automático + Gerenciamento de Caixas ATM). Ficam fora deste escopo:

  • Restante do Nacional — Averbação, Fechamento/Faturamento e Relatórios. Observação: um conjunto reduzido (AVB/FEC/REL/GCX) chegou a ser automatizado como cobertura extra e está verde no repositório, mas não integra a entrega Allianz e não conta no placar acima.
  • Demais módulos do launcher — Internacional, Conversor, Importar/Exportar, Interface WI/Siscomex, Liberação de Cobertura, Gestão e Tabelas. Não mapeados/automatizados (fora de escopo).

Login positivo e o launcher são exercidos transversalmente por todos os CTs em escopo (fixture de login do conftest); os CTs de login negativo (senha expirada / usuário inativo) ficam fora do escopo Allianz.

Riscos & observações
  • Bug #8347 — tela Caixas Postais RCTR-C retorna HTTP 500 intermitente. Os cenários têm retry; se persistir, o CT faz skip com registro.
  • Bug #8346 — API GetApolicesByCxPostal retorna 500 reproduzível (aberto na sustentação, tag NSONE).
  • Cloudflare/UA — a API NSOne bloqueia User-Agent Python (403/1010); a suíte manda UA de browser.
  • Massa no Averba escassa em HML — a descoberta cruza banco × Averba; para o ATM install pode ser preciso criar terminal (POST) como pré-requisito.
  • Mutação da AT&M — os CTs de Instalação ATM enviam POST ao Averba (HML); criar terminal é irreversível — estratégia de idempotência (guard de duplicado da tela + migrar/atualizar o existente).
  • Regra 9 — não generalizar regra de um ramo para outro.
