2. Descrição

Hoje o worker despreza a DUIMP na carga quando o tipo de transporte não vem preenchido/válido — mensagem exata medida em HML AXA: Desprezada - DUIMP com tipo de transporte inválido ( INDEFINIDO) (62 linhas 'D', mais recente 27/11/2025). A averbação se perde mesmo quando só esse dado secundário faltava.

O #8258 condiciona o desprezo às duas faltas juntas: sem tipo de transporte e sem veículo transportador → despreza na carga com mensagem citando as duas informações. Sem tipo mas com veículo → a carga segue normal (grava em tb_itf_smx_dcl_pnd_dui) e a checagem move para o processamento: ao montar o enquadramento/averbação, o worker grava um registro com código de erro novo em tb_itf_smx_dcl_pnd_err e atualiza o status da DUIMP para Inconsistente em tb_itf_smx_dcl_pnd_dui. O usuário corrige via Interface WI x Siscomex → Declarações Adições → Acerto de Inconsistências (DE/PARA). Como a Quorum manda um único valor por DUIMP (replicado pelo worker em cada linha de item — atribuição de e_trp_smx dentro do laço) e tipo de transporte não é critério de agrupamento (consignatário + Incoterm + tipo de DUIMP), uma correção no nível da DUIMP resolve o bloqueio de todos os grupos.

-- Q2: linha(s) de uma DUIMP na tabela de controle (status, mensagem, via/veículo no JSON)
SELECT u_seq, u_dcl_imt_smx, sts_prc, t_sts_prc, d_usu_inc,
       SUBSTRING(t_json_wi, CHARINDEX('VIA_TRANSP', t_json_wi), 80)  via_json,
       SUBSTRING(t_json_wi, CHARINDEX('NOME_VEICULO_TRANSP', t_json_wi), 60) veiculo_json
FROM tb_itf_smx_ctl_prc_dui WHERE u_dcl_imt_smx = '<DUIMP>' ORDER BY u_seq;

-- Q3: linhas da DUIMP gravadas para processamento (via, veículo, status, itens)
SELECT u_dcl_imt_smx, u_adl_smx, u_adl_itn_smx, e_trp_smx, t_vei_tpr_smx,
       e_dcl_smx, q_itn_agp, c_hsh_agp, d_usu_inc
FROM tb_itf_smx_dcl_pnd_dui WHERE u_dcl_imt_smx = '<DUIMP>' ORDER BY u_adl_smx, u_adl_itn_smx;

-- Q4: erros de processamento da DUIMP (jornada de inconsistência)

SELECT u_avb_dfv, d_mov_vgm FROM tb_mov_avb_int_cit WHERE u_di LIKE '<DUIMP>%';
