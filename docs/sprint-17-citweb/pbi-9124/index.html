2. Descrição

O card é o desdobramento, para o cadastro de apólice, da extinção do IOF tratada no módulo Tabelas pelo PBI-9120. O gatilho da regra é o valor de IOF da seguradora (Tabelas → Parâmetros → Custo/IOF, grupo IOF → campo Percentual — um único percentual por tenant, tabela tb_iof_cit.o_iof): com 0,00, a tela de Dados da Apólice deixa de apresentar a opção de IOF; com valor > 0, nada muda. A flag da apólice persiste em tb_apo_nac_cit.i_iof_cme / tb_apo_int_cit.i_iof_cme (oráculo de banco).

Verificação in loco (14/10/2026, AXA HML, somente leitura — feature gravada em features/apolice-nacional/dados-apolice-flag-iof.md): a seção "Dados para Cobrança de Fatura Mensal" existe nas telas de Dados da Apólice do Nacional e do Internacional com o mesmo user control — flag IOF = ctl00_ContentPlaceHolder1_chkIof (checkbox simples, sem campo-texto associado — diferente de Custo/Pr.Manutenção que têm Valor/Taxa). Baseline atual (IOF da seguradora = 7,38%): flag IOF exibida; em form Novo vem marcada por default (desabilitada até escolher Segurado); em edição vem habilitada com o estado da apólice (ex.: apólice 333/ramo 54 com IOF desmarcado). "Campo de IOF" e "flag de IOF" citados no CA correspondem, nesta tela, ao mesmo elemento (a checkbox) — não há campo numérico de IOF no cadastro de apólice. [v1.3 — L1] O estado "desabilitada até escolher Segurado" descrito acima foi superado pela medição de 19/10 (CT-APO-006): o oráculo do estado da flag é o baseline medido, não esta descrição.
⚠️ Pré-condição IOF = 0,00 depende do PBI-9120 (ou de semeadura via banco). Hoje a tela Tabelas → Custo/IOF recusa 0,00 ("Informar o Percentual de IOF." — validado em 13/10). Se na execução o fix do PBI-9120 ainda não estiver em HML, a pré-condição será semeada direto no banco (UPDATE tb_iof_cit SET o_iof = 0 — HML, com restauração para 7,38 ao final). A ordem de deploy dos dois PBIs não altera o resultado esperado deste plano.
