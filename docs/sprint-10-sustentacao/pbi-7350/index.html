📋 Contexto do defeito (PBI #7350 · TECSD-38734)

O quê: ao incluir DUIMPs para o importador GENERAL MILLS (CNPJ 61.586.558/0025-62, despachante Schenker), o CITWEB gravava as declarações na apólice expirada 0106220001985 (vig. 2023–2024) em vez da vigente 0106220002616 (vig. 31/08/2024–31/08/2025), impedindo o faturamento correto. Sistemático para todo pacote do Schenker.

Causa-raiz (código): em ObtemApoliceImportadorConsignatario, no ramo "faturamento pelo importador" (i_fat_prf != "C"), o método definia o segurado mas não retornava, caindo no fallback ListarComImportadorCossignatario (sem filtro de data, order by cd_apolice desc) que sobrescrevia a apólice já selecionada por data (ListarPorImportadorConsignatarioApoliceData(..., dataSaida)) pela apólice errada.

Correção: return new KeyValuePair<bool,string>(true, "") logo após definir o segurado — preserva a apólice selecionada por vigência. + log de exceção no catch. commit: 995e7371f · PR: 1345 / 1250 · branch: AXA_7350_DUIMP_HML.

ℹ️ Critério de Aceite (Cenário 4) coberto

  • Dado múltiplas apólices para o mesmo importador/subgrupo (histórico + vigente), quando associar uma DUIMP/DI, então a apólice selecionada deve ser aquela cuja vigência (início ≤ data de referência ≤ fim) contém a data de referência (data de saída / embarque = d_sda_vgm) — CT-ENQ-001, CT-ENQ-002.
  • Correção de código validada (early-return preserva seleção por vigência) — CT-ENQ-003.
  • Massa das apólices do card confirmada no ambiente — CT-ENQ-004.

⚠️ Limitações e transparência desta execução

  • O cenário exato do card (pacote Schenker → General Mills) não é reproduzível no HML Alfa: no WI o importador é identificado por um código alfanumérico (ex.: AAMP6803000193), não pelo CNPJ do GM; a relação/subgrupo do CNPJ GM não existem no Alfa e o pacote Schenker não está na fila WI. Dependência de dado do WI-Quorum (sistema externo legado) → CT-ENQ-005 BLOQUEADO (dependência externa), não falha do fix.
  • A verificação do CA foi feita a nível de dado (staging tb_itf_smx_dcl_pnd* × vigência tb_apo_int_cit) sobre TODAS as declarações carregadas sob o build corrigido — evidência mais forte que um único PROTCARGA.
  • Card em homologação paralela pela conta André Madeira (task 7819). Este plano é a verificação independente executada sob a conta do Wesley; não substitui nem sobrescreve o ciclo do André no AzDO.
