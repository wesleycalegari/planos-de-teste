2. Descrição

A home (/app) intermitentemente demora ~15s e exibe 0 em todos os indicadores, com HTTP 200 — indistinguível de "não há registros". Root cause: um catch (Exception) genérico engole o cancelamento (TaskCanceledException/OperationCanceledException) e devolve 0; o axios (timeout: 15_000) aborta quando as 4 COUNT(*) em série somam >15s (banco frio) e derruba as 4 de uma vez. Speckit match: AP-002 — Exception Swallowing (repo .speckit/known-issues/anti-patterns.md).

Objetivo do QA: provar que falha/cancelamento NUNCA vira 0 (mostra estado de indisponibilidade), que a resposta é <2s inclusive com banco frio, e que há a regressão que teria pego este bug — sem regressão de autenticação.

3. Escopo

INOUT
Contrato "indisponível ≠ 0"; propagação de cancelamento; performance <2s (frio); regressão de cancelamento e de tabela ausente (SQL 208); autenticação; conferência de valores por tenant; validação de negócio do COUNT(*). Epic 7921 (gadgets/persistência de preferência); UI de configuração de dashboard; migração para DashApi .NET7 (estratégia B, não aprovada).

4. Pré-requisitos

  • Fix (estratégia A) deployado em HML com o endpoint GET /api/dashboard/stats existente e autenticável. Hoje NÃO satisfeito.
  • Credenciais por env (HML_<SEG>_*) — definir tenants de amostra na execução (multi-tenant).
  • Capacidade de forçar banco "frio" (pós-ociosidade) e de simular cancelamento / SQL 208 (ambiente de teste).
