2. Descrição

O fluxo de CI/CD do CITWEB prevê o ambiente de staging entre HML e PRD. Seis seguradoras já em produção ainda não possuem STG: EZZE, STG, SUHAI, SURA, TOKIO e ZURICH (levantamento pelas release definitions — seguradoras com release PRD e sem release STAGING). O card cria, para cada uma: DNS {seg}-stg-faturamento.nsseg.com.br, server block no Nginx (HTTPS), banco de staging e a release CITWEB - <SEG> - STAGING com variable groups completos, encerrando com deploy e a aplicação carregando a tela de login.

Oráculo da tela de login de staging (medido em 28/09/2026 nos stagings existentes): a página /login/ responde HTTP 200 com título <SEGURADORA> STAGING - MÓDULO Login CIT - <data do build> e campos nomeUsuario / senhaUsuario. Referências medidas: NSTECH STAGING (build 22/09/2026), STARR STAGING (22/09/2026), AXA STAGING (16/09/2026). A data do título é a data do build — nos ambientes novos deve refletir o deploy da release recém-criada.
Atenção — seguradora “STG”: o host dela é stg-stg-faturamento.nsseg.com.br (prefixo da seguradora STG + sufixo do ambiente staging). Não confundir com o sufixo de ambiente; o CT-ENV-001 valida explicitamente que DNS/Nginx/release da “STG” se referem à seguradora, não a um alias de ambiente.

3. Escopo

In scope

  • Validação da lista final de seguradoras sem staging (CA1).
  • Conferência documental dos chamados de infra (DNS, Nginx, banco) — abertos, concluídos e linkados ao card (CA2/CA3/CA4).
  • Smoke somente leitura por ambiente novo: DNS resolve → HTTPS/certificado válido via Nginx → aplicação de staging responde → tela de login CITWEB carrega (CA2/CA3/CA6).
  • Release definitions CITWEB - <SEG> - STAGING criadas no padrão, com variable groups completos e sem config vazia (CA5, KI-005 citado no card).
  • Deploy executado com sucesso pela release em cada ambiente (CA6).
  • Regressão: stagings existentes continuam no ar após as mudanças de DNS/Nginx.
  • Evidências anexadas ao card (CA7).

Out of scope

  • Autenticação (login efetivo) nos ambientes STG — o CA exige a tela de login carregando; os bancos de staging nascem agora e não há usuário de QA provisionado. Convenção vigente: QA não cria/edita/exclui dados em staging (somente leitura).
  • Seguradoras sem ambiente de produção (somente HML/DEV) e variantes -ALFA (fora do escopo declarado no card).
  • Testes funcionais de negócio em STG (averbação, fatura etc.).
  • Produção — QA não testa em PROD (N/A).
