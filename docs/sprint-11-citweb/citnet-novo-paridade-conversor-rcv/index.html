C3CC VKMCML (prêmio por faixa de KM) grava prêmio R$ 0,00 — no CITNET atualALTO▶

Fato observado

Averbação da apólice 2 / subgrupo 1, cuja CC define R$ 77,77 para a faixa 0–1000 km, informando KM = 500 no arquivo: o km foi gravado (u_km_vgm = 500) mas o prêmio saiu R$ 0,00 com f_cml_bsc = 0. Não é problema de integração de quilometragem — o km veio do próprio arquivo.

Causa no código

CLSNACCALC.CalcularPremioRCV tem branch apenas para PRFX, PRVCML e TPP — não existe tratamento para VKMCML, então o método cai no return 0 final. Reforçando: ObterCondicaoComercialRCV carrega as linhas da CC com ORDER BY d_ini_vig DESC em um while que sobrescreve o objeto a cada leitura e não filtra a faixa de KM — ou seja, mesmo que houvesse o branch, a faixa selecionada seria arbitrária.

Dimensão nesta base

  • 62 apólice/subgrupo têm CC VKMCML com valor de prêmio cadastrado (v_prm > 0).
  • Averbações RCV de subgrupos VKMCML na competência ≥ 202601: 86 com prêmio zero contra 2 com prêmio > 0.

Este é um defeito do CITNET atual, não uma divergência entre os dois. Entra no comparativo porque define o alvo: se o novo copiar o comportamento, herda o prêmio zerado; se implementar o cálculo por faixa, vai divergir do atual — e a decisão de qual é o correto é de Produtos.

C4CC PRVCML: os 4 tipos de viagem testam o campo errado no código (risco de prêmio zero)A CONFIRMAR▶

Fato observado no código

Em CalcularPremioRCV, os quatro case do tipo de viagem testam sempre v_vgm_urb, mas retornam o campo do respectivo tipo:

case "EST": return condicaoRcv.v_vgm_urb != null ? Convert.ToDecimal(condicaoRcv.v_vgm_uf_int) : 0;
case "VIZ": return condicaoRcv.v_vgm_urb != null ? Convert.ToDecimal(condicaoRcv.v_vgm_uf_viz) : 0;
case "NVZ": return condicaoRcv.v_vgm_urb != null ? Convert.ToDecimal(condicaoRcv.v_vgm_uf_nao_viz) : 0;

Consequência: se o subgrupo tem valor para "mesmo estado / vizinho / não vizinho" mas não tem valor urbano, o prêmio volta 0.

Status: risco identificado, ainda não comprovado em movimento

69 apólice/subgrupo desta base estão exatamente nessa configuração (v_vgm_urb nulo/zero e algum dos outros > 0). Porém nenhuma averbação da competência ≥ 202601 pertence a esses subgrupos, então não há movimento real para comprovar o efeito aqui. Requer massa dirigida (averbação PRVCML com percurso interestadual em subgrupo sem valor urbano) — está na lista do que falta.

Contexto de volume: PRVCML é o tipo de CC mais usado no RCV nesta base (299 apólice/subgrupo), e há 1.255 averbações de 2026 com prêmio zero em subgrupos PRVCML — número que sugere o problema, mas que também pode se explicar por cadastro sem valores; por isso está como "a confirmar" e não como defeito comprovado.
