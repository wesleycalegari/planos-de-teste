2. Descrição

O time acordou com o QA a meta de 30% de cobertura em código novo/alterado, garantida por um gate de 80% de cobertura de diff por PR que bloqueia o merge quando não atingido. A meta anterior (30% da base inteira, ~564 mil linhas hoje com 0% de cobertura) foi descartada por inviabilidade. O PBI 8254 entrega a Mini RFC que desenha essa esteira: pipeline dedicada de PR-gate (build + teste + diff coverage, sem o motor de análise estática do Sonar), mecanismo de cálculo de diff coverage, Branch Policy no Azure DevOps e processo de exceção para código legado acoplado a banco.

Contexto técnico já confirmado no card: a instância SonarQube é Community Edition 8.9.10 — PR decoration nativo (Rota A) foi descartado (feature de edição paga); a Rota B (script próprio de diff coverage) é a única via. Hoje nenhum gate automatizado roda na PR para hml (as pipelines existentes disparam só pós-merge). As tasks filhas complementam a RFC: #8330 (refinamento de testabilidade — Extract-and-Override, ADR-010, custo por card) e #8373 (piloto prático em Repository/PaisDesbloqueioRepository.cs, método VerificarDesbloqueio — 72 linhas, 1 método público, 1 branch real).
