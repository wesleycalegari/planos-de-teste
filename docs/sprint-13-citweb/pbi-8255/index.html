2. Descrição

Hoje, ao dar carga, o worker grava o JSON inteiro da DUIMP em tb_itf_smx_ctl_prc_dui independente do resultado — mas quando a DUIMP não tem data de saída, ele a despreza definitivamente (grava sts_prc='D' com a mensagem exata Desprezada - DUIMP com data de saída inválida — 109 linhas nessa condição em HML AXA, medido em 27/08/2026). A averbação se perde e é preciso esperar novo envio da Quorum.

O #8255 muda o destino desse caso: a DUIMP sem data de saída passa a ser retida como Inconsistente (sts_prc='I') na mesma linha, com o JSON preservado. Quando a data for corrigida pelo CITWEB (tela do #8256), a linha vira sts_prc='R' (Reprocessar) com o JSON já atualizado — e, no ciclo seguinte, o worker lê o JSON gravado na própria tabela (tag de data de saída), sem nova chamada à WI/Quorum, seguindo o fluxo normal de enquadramento/averbação. Nenhuma tabela ou coluna nova: só dois valores novos na coluna de status (hoje P/E/C/D).
