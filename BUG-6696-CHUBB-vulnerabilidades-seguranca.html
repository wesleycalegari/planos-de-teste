2. Descrição

Foram identificadas as seguintes vulnerabilidades na aplicação CITNET CHUBB e corrigidas na task 6766 (Done):

  1. Headers de segurança ausentes — Referrer-Policy e Permissions-Policy não implementados
  2. Stack trace exposto — mensagens de erro detalhadas expostas ao usuário, permitindo reconhecimento de infraestrutura
  3. Parâmetros URL refletidos sem sanitização — ?erro= e ?trace= refletidos na página, habilitando phishing/defacement
  4. AntiForgery Token inválido — erro de CSRF token na rota /AverbacaoInternacional/AverbacaoExportacao após atualização
Contexto: a task 6703 (Done) registrou o erro específico de AntiForgery na exportação de averbação internacional: HttpAntiForgeryException — The anti-forgery cookie token and form field token do not match.
Este plano valida que todas as 4 vulnerabilidades foram corrigidas.

3. Escopo

In scope:

  • Presença de headers Referrer-Policy e Permissions-Policy nas respostas HTTP
  • Ausência de stack trace em mensagens de erro ao usuário
  • Não reflexão de parâmetros ?erro= e ?trace= na página
  • Funcionamento correto do AntiForgery token em AverbacaoExportacao
  • Regressão funcional — funcionalidade do CITNET CHUBB não impactada pelas correções

Out of scope:

  • Scan completo de vulnerabilidades (responsabilidade da ferramenta Appscan/VeraCode)
  • Outras seguradoras além de CHUBB
  • Vulnerabilidades de bibliotecas desatualizadas (cobertas pelo card 6694)

5. Casos de Teste

GRUPO 1 — Headers de Segurança HTTP
CT-SEC-001 P1 Bloqueante Response HTTP do CITNET CHUBB inclui header Referrer-Policy Pré-condições Browser Chrome/Edge com DevTools. CITNET CHUBB HML acessível. Passos
  1. Abrir DevTools (F12) → aba Network
  2. Acessar https://chubb-hml-faturamento.nsseg.com.br/citnet/
  3. Selecionar qualquer request HTML da listagem
  4. Verificar os Response Headers da requisição
  5. Procurar pelo header Referrer-Policy
Resultado esperado O header Referrer-Policy está presente nas respostas HTTP do CITNET CHUBB com um valor definido (ex.: strict-origin-when-cross-origin ou similar). Tipo Segurança
CT-SEC-002 P1 Bloqueante Response HTTP inclui header Permissions-Policy Passos
  1. Mesmos passos do CT-SEC-001
  2. Procurar pelo header Permissions-Policy nos Response Headers
Resultado esperado O header Permissions-Policy está presente com valor definido que restrinja features desnecessárias. Tipo Segurança
GRUPO 2 — Exposição de Stack Trace
CT-SEC-003 P1 Bloqueante Erros de aplicação não expõem stack trace ao usuário Pré-condições CITNET CHUBB HML. Necessário provocar uma condição de erro (ex.: URL inválida, parâmetro incorreto). Dados de entrada URL com parâmetro inválido: https://chubb-hml-faturamento.nsseg.com.br/citnet/Home/Error?msg=teste Passos
  1. Logar no CITNET CHUBB com VOIDR-NSTEC / NS-Vo1dr@b (Filial = Selecione…)
  2. Tentar acessar uma rota que cause erro (URL inválida ou com parâmetro forçado)
  3. Observar a mensagem de erro exibida ao usuário
  4. Verificar se há informações técnicas (nome de DLLs, caminhos de servidor, stack trace) expostas
Resultado esperado A mensagem de erro exibida ao usuário é amigável e genérica, sem stack trace, caminhos do servidor ou informações técnicas de infraestrutura. Tipo Segurança / Negativo
GRUPO 3 — Reflexão de Parâmetros URL
CT-SEC-004 P1 Bloqueante Parâmetro ?erro= na URL não é refletido (renderizado) na página Dados de entrada URL: https://chubb-hml-faturamento.nsseg.com.br/citnet/?erro=<script>alert(1)</script> Passos
  1. Logar no CITNET CHUBB
  2. Adicionar manualmente na URL o parâmetro ?erro=<script>alert(1)</script>
  3. Pressionar Enter para carregar a URL
  4. Verificar se o conteúdo do parâmetro é exibido ou executado na página
  5. Verificar se aparece algum alert/popup ou se o texto do script aparece na tela
Resultado esperado O conteúdo do parâmetro ?erro= NÃO é refletido/renderizado na página. Nenhum alert popup aparece. A página exibe mensagem de erro genérica ou redireciona para uma página de erro adequada. Tipo Segurança / XSS
CT-SEC-005 P1 Bloqueante Parâmetro ?trace= na URL não é refletido na página Dados de entrada URL com ?trace=qualquer_valor_injetado Passos
  1. Adicionar o parâmetro ?trace=testeinjecao na URL do CITNET CHUBB
  2. Carregar a URL
  3. Verificar se o valor "testeinjecao" aparece em algum lugar da página
Resultado esperado O valor do parâmetro ?trace= NÃO é exibido na página. Sem reflexão de conteúdo controlado pelo usuário. Tipo Segurança
GRUPO 4 — AntiForgery Token (CSRF)
CT-SEC-006 P1 Bloqueante AntiForgery token válido na rota AverbacaoExportacao — sem erro 0x80004005 Pré-condições CITNET CHUBB HML. Apólice com averbação internacional disponível para exportação. Passos
  1. Logar no CITNET CHUBB (VOIDR-NSTEC / NS-Vo1dr@b, Filial = Selecione…)
  2. Navegar até Averbação Internacional
  3. Localizar uma averbação existente
  4. Acionar a funcionalidade de Exportação (AverbacaoExportacao)
  5. Verificar se o sistema processa a exportação sem erro de AntiForgery
  6. Verificar que não aparece erro "anti-forgery cookie token and form field token do not match"
Resultado esperado A exportação de averbação internacional é processada sem erro de AntiForgery. Sem HttpAntiForgeryException. Tipo Segurança / Funcional
GRUPO 5 — Regressão Funcional
CT-SEC-007 P2 Importante Funcionalidades principais do CITNET CHUBB não impactadas pelas correções de segurança Passos
  1. Acessar o CITNET CHUBB normalmente (login com credenciais válidas)
  2. Verificar que o menu principal carrega corretamente
  3. Navegar até Averbação Internacional → verificar que a tela carrega
  4. Navegar até Averbação Nacional (se disponível) → verificar carregamento
  5. Verificar que formulários submetem sem erro relacionado a AntiForgery
Resultado esperado Todas as funcionalidades principais do CITNET CHUBB funcionam normalmente. As correções de segurança não introduziram regressões funcionais. Tipo Regressão
